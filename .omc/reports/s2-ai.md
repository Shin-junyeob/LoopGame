## 측정 정의

- 하드 지표: 필터를 거치기 **전** 모든 후보에 대해 잼(마스크가 보장하는지 확인). 음 개수 변화는 입력(지터된 녹음) 대비
- 통계 지표: 후보별로 격자 오차 비율(약 ≤ 0.6 / 강 ≤ 0.2, 입력 대비)과 입력 대비 F1(약 ≥ 0.85 / 강 ≥ 0.65)을 모두 만족하는지. 필터 전 후보 단위
- Ablation: 사용자에게 보이는 1순위 보정안(F1 같으면 덜 바꾼 쪽 먼저)을 지터 전 원본과 비교. 계획 정의 열은 ±2반음 허용 F1(`Metrics.onsetF1` 기본값), 정확 열은 `pitchTolerance: 0`. 보정안이 없으면 입력 그대로로 계산. 규칙 기준선 = 가장 가까운 16분 + 가장 가까운 허용 음(음계, 강박은 코드톤) + 완전 중복 제거. paired bootstrap 2,000회, 시드 2026
- 지연: `Corrector.suggest` 1회(빔 폭 8, 후보 4개 + 필터), M5 맥북 에어 release 빌드. debug 빌드는 더 느림

## 튜닝 기록 (모두 학습 내부 검증셋에서, holdout은 최종 1회만)

검증셋 = 학습 패턴을 그룹 단위로 다시 80/20 나눠 80%로 모델을 만들고 20%를 지터한 75개×4 (`tools/train/val/`, 별도 시드라 holdout과 번들 모델은 바이트 단위로 동일함을 확인). 숫자는 "후보 1개만 둘 때 원본 복원 F1 − 규칙 기준선"(×1000).

| 시도 | 전체 | 메모 |
|---|---|---|
| 초기 설정(약 4·12, 2·8 / 강 0.8·5, 0.3·3), holdout에서 처음 잼 | −1 (CI [−4, +2]) | **NO-GO** — 삭제가 진짜 음을 지움, 이 숫자만 holdout에서 봤음 |
| 삭제 페널티 6~12 (가까움 1~4) | −56 ~ +0.5 | 삭제할수록 나빠짐(코드 −65까지) |
| 삭제 사실상 끔(100), 가까움 0.3~10 | +1.9 ~ +3.7 | 가까움 3~6에서 최고(±2반음 허용 F1 기준이라 음높이 이득은 이 숫자로는 판단 불가) |
| n-gram 차수 2/3/4/5 × 할인 D 0.5/0.75/0.9 | 2.8 ~ 3.6 (삭제 끔) | 차이가 잡음 수준 → 기본값(3차, D 0.75) 유지 |
| 최종(약 3·100, 1.5·30 / 강 1·16, 0.5·12), 4후보 전체 | +3 (CI [+1, +6]) | 이 설정으로 holdout 1회 → 위 결과 |

## 한계 (정직하게)

- **이득은 작다**: ±2반음 허용 기준 +0.4%p. 이 지표는 ±1–2반음 틀린 음높이를 맞은 것으로 세므로 음높이를 고친 효과를 거의 반영하지 못함. 정확한 음높이 기준으로 보면 음높이 선택 이득은 코드 반주에서만 유의(+1.8%p [+0.6, +3.0])하고 베이스(+0.6 [−1.0, +2.3])·멜로디(−0.2 [−2.0, +1.8])는 0과 구분 안 됨 — "마스크 안 음높이 선택이 이득을 낸다"는 주장은 코드 반주에 한해서만 성립. 삭제는 검증셋에서 일관되게 손해라 1순위(약한 보정)는 삭제를 끄고, **음 추가는 구현하지 않음**(삭제부터 손해라 시도하지 않음). 빠진 음·끼어든 음 복원은 못 함
- **통계 지표는 구조상 통과(게이트 정보가 거의 없음)**: 위치 후보가 ±1/8박(60틱) 안의 16분 격자뿐이라 모든 후보의 격자 오차가 0이고, F1은 ±120틱·±2반음 허용이라 거의 1. 통과율 100%·F1 0.99는 보정이 좋다는 증거가 아니라 후보 생성 방식의 결과
- 베이스·멜로디는 두 기준 모두 역할 단독 CI가 0을 포함함. 드럼은 음높이 선택이 없어 이득이 작음
- holdout을 초기 설정 1회 + 최종 1회, 총 2회 봄. 그 사이 조정은 검증셋 숫자로만 함
- 지연은 Mac 수치. iPhone 15 Pro / iPad Air 5 측정은 사용자 단계
